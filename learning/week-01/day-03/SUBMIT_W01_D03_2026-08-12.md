Independent explanation I can give now:
- Alignment constrains where an object/member can begin, while padding is extra space inserted to satisfy that alignment.
- Tail padding helps consecutive struct objects, such as array elements, begin at correctly aligned addresses.
- Member order can change struct size because different layouts require different amounts of padding.
- Little-endian stores the least-significant byte at the lowest memory address.
- Raw struct serialization is risky because layout/padding and endian can differ across compiler, ABI or platform.
